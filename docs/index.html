PSXRecompStudio

A development environment for PlayStation 1 (PS1 / PSX) binary analysis, MIPS R3000A analysis, static recompilation research, reverse engineering, and native porting experiments.

PSXRecompStudio focuses on building and validating the technical foundations needed for reliable PlayStation 1 recompilation. It does not yet recompile complete commercial PS1 games into native ports.

View the repository on GitHub

What works today

  • R3000A / MIPS I instruction modeling, decoding, memory behavior, delay-slot behavior, exceptions, interrupts, and deterministic Golden Trace validation.
  • Disc-analysis flow covering CHD input, ISO 9660 structures, PS-X EXE extraction, MIPS analysis, basic blocks, and control-flow graph extraction.
  • A synthetic MIPS recompiler vertical slice plus bounded real-ROM-derived function proofs, whole-corpus coverage reporting, deterministic host C generation, and differential validation against the interpreter.
  • Runnable generated-host artifacts and a headless psxrecomp recompile / psxrecomp run CLI with classified JSON results and privacy-safe diagnostic bundles.
  • Partial Runtime hardware support including BIOS HLE, production-reachable interrupt/timer/DMA/memory/SIO0/SPU register state, and a managed GPU model with minimal rasterization and deterministic frame snapshots.
  • Compiler-enforced architecture boundaries and a stable C ABI shared by the C# layer and the mixed C++/Rust native core.

Not yet implemented

  • End-to-end recompilation of complete commercial PlayStation 1 titles.
  • A finished runtime for native PS1 game ports.
  • Complete GPU, SPU, CD-ROM, MDEC, and GTE support.

Technology stack

C# and .NET

Domain logic, analysis, validation, tests, and managed interop code.

Avalonia

Cross-platform desktop application shell and future analysis workflows.

C++, Rust, and CMake

Native CPU, memory, and hardware-oriented components coexist behind a stable C ABI while semantics migrate incrementally to Rust.

C ABI and P/Invoke

A narrow managed/native boundary keeps C++ and Rust implementation details out of C#.
